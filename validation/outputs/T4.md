# T4 — Artifact Accession Intake (Whitcombe Museum, registrar wizard)

Persona: museum registrar (internal specialist, desktop, a few sessions per month). Ranked tasks:
1) record the object and its provenance accurately, 2) document condition with photos before the
object moves, 3) assign storage and finish with a defensible accession record.

---

## 1. Design Brief

```
DESIGN BRIEF
- Use case: Museum registrar accessions a newly acquired artifact — 5-step desktop intake
  (object details → provenance → condition + photos → storage → review); used a few times a month.
- Pattern + variant: forms / wizard — custom sidebar wizard (persistent rail + a!match step bodies)   [Stage 1: S5]
- Recipe: Premium Editorial  ·  Density: 2                       [Stage 2: weekly-manager × premium-aspirational]
- Palette (5+ hexes): page #f8f6f0 cream, rail #f3f3f3, brand band #111111, cards #ffffff
  (shadow-not-border), metallic accent #deaf3e bar / #eac251 eyebrow (= theme ACCENT gold, ≤3
  touchpoints), text #111111 with #666666/SECONDARY meta; semantic reserved — NEGATIVE for
  validation errors only, nothing red at rest.
- Header treatment: flush full-bleed near-black band (#111 self-colored card in the header slot,
  contentsPadding NONE) carrying the museum wordmark + gold registration eyebrow; NO page title and
  NO billboard — the page's identity lives in the rail wall label.
- Signature moves (≥3, from recipe or anti-corporate menu):
  1. Gallery wall-label rail — full-height #f3f3f3 flush card stack: caps accession eyebrow →
     object lockup → source/received meta, finished with a gilt rule — levers: stacked
     a!cardLayout(style:"#f3f3f3", marginBelow:"NONE") + EXTRA_TALL spacer-card illusion +
     decorativeBarPosition:"TOP"/decorativeBarColor:"#deaf3e"; a!milestoneField(orientation:
     "VERTICAL", stepStyle:"DOT", active: local!step) as the progress spine beneath it.
  2. Full-bleed band architecture — #111 museum slab in the header slot — levers:
     a!headerContentLayout(contentsPadding:"NONE") + self-colored card padding:"MORE"; gold
     #eac251 typed-caps eyebrow in rich text (gold text only on the dark band, ≥4.5:1).
  3. Labels demoted, values promoted — typed-caps SMALL/SECONDARY eyebrow sections (H2) over
     COLLAPSED fields; step heading is a real H1 at MEDIUM — levers: a!sectionLayout(labelSize,
     labelColor, labelHeadingTag) + accessibilityText on collapsed fields.
  4. Choice cards instead of a dropdown for the condition grade — lever: a!cardChoiceField(
     cardTemplate: a!cardTemplateBarTextStacked, maxSelections: 1), uniform primary/secondary
     text on all four cards (no icons on any, per the all-or-none rule).
  5. Designed photo-tray states — attached-photo rows (TINY stamp tile | filename + view |
     right-pinned date via sideBySide MINIMIZE) ⇄ a designed empty state (EXTRA_LARGE pale
     icon + sentence), swapped with complementary showWhen on one boolean.
- Deliberately omitted: an art-directed billboard hero of the object. At intake no photography of
  the artifact exists yet — the condition step is what creates it — and Premium Editorial's rule is
  art-directed or nothing, so the header stays typographic instead of faking a photo.
```

Density evidence (claimed 2): one topic per viewport — rail + a single white work card; 5 field
clusters on the whole step; card padding "MORE", terminus marginAbove "EVEN_MORE"; no grids, no
charts.

## 2. Layout skeleton

Rendered state: `local!step: 3` → "Condition & Photos" (3 of 5). Steps: Object Details →
Provenance → Condition & Photos → Storage Assignment → Review & Accession (review step included
because an accession record is consequential; fixes after filing are expensive).

```
   │        │  ├─ photo rows ×3: [TINY stamp tile | filename STRONG + view · light SMALL SECONDARY
   │        │  │                  | "Attached Aug 3" MINIMIZE] with hairlines between
   │        │  ├─ ⇄ designed empty state (portrait icon #d9d9d9 EXTRA_LARGE + sentence),
   │        │  │    complementary showWhen on local!hasPhotos
   │        │  └─ FILE-UPLOAD "Add Photos" (placeholder = format hint only)
   │        ├─ SECTION H2 "EXAMINATION" → COLUMNS [1:1]: Examined By dropdown | read-only
   │        │  date echo (rich text, no input chrome — exam date IS the intake date)
   │        └─ SECTION divider=ABOVE marginAbove=EVEN_MORE:
   │           [Cancel LINK · Back OUTLINE  ←→  "Next: Storage Assignment" SOLID]   (one SOLID)
   └─ (empty AUTO flank)
```

Phone/tablet behavior (stated per README even though desktop-first): outer columns stack at
PHONE/TABLET_PORTRAIT so the wall label + milestone become the top block — progress cues survive
(the ins-quote-wizard rail-shedding risk avoided); the EXTRA_TALL rail spacers and empty flanks are
desktop-only (`showWhen: not(a!isPageWidth(...))`), so stacking leaves no dead blocks; buttons and
the examination pair stack full-width by default; header band is not fixed.
