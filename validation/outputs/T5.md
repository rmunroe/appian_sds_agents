# T5 — Foster Placement Record View (Cedar Hollow Animal Rescue)

## 1. Design Brief

```
DESIGN BRIEF
- Use case: Shelter coordinator (Rosa Fuentes) works one foster placement — animal facts + status,
  open tasks, a comment thread with the foster family, and event history; desktop + phone.
- Pattern + variant: record-views / subject + related (freeform header; comment-thread S12 hosted
  inside the view as its widget variant)                                        [Stage 1]
- Recipe: Ops Control, warm chips  ·  Density: 4                                [Stage 2]
  (operator record view: 3-column body, masthead + 5-node timeline + 6-fact card + 4 task rows +
  thread + history feed per viewport; list containers padding "NONE"; metadata at SMALL)
- Palette (5+ hexes): page #f4f2f1 warm greige; cards #ffffff shadow-not-border; pastel chip set
  #d19fcb (foster family) / #9dd0aa (shelter staff + IN FOSTER status) / #79b096 (progress-done) /
  #eccd5f (supplies) / #9db6d0 (paperwork); duotone type pairs #d7e5f3/#3d85c6 (medical),
  #d7f3e0/#459b20 (family visit/call); semantic NEGATIVE token — exactly one OVERDUE tag;
  text #54514e headings, #666666 metadata, #d9d9d9/#666666 future timeline steps.
- Header treatment: flush masthead weld — EXTRA_SHORT photo billboard (Biscuit) butted via
  marginBelow "NONE" onto a white identity-band card (eyebrow placement #, name LARGE STRONG,
  status chips, end-aligned OUTLINE actions). No colored band — Ops Control prohibition; color
  lives in the chips.
- Signature moves (≥3, from recipe or anti-corporate menu):
  1. Photo→identity masthead weld — a!billboardLayout(height:"EXTRA_SHORT", marginBelow:"NONE")
     fused to a white a!cardLayout(marginBelow:"NONE") [cookbook 1.4; nonprofit move 1].
  2. Pastel color vocabulary, not decoration — stable entity/type coding: plum-pink #d19fcb =
     foster family people, mint #9dd0aa = shelter staff, blue duotone #d7e5f3/#3d85c6 = medical
     (vet avatar AND vet task tile), green duotone = family visit, gold = supplies, dusty blue =
     paperwork [TINY a!stampField backgroundColor/contentColor; recipe chips].
  3. Red rationed to one alarm — NEGATIVE appears exactly once, the OVERDUE tag on the vaccine
     task [a!tagItem(backgroundColor:"NEGATIVE"); recipe move 3].
  4. Whole-card linked task rows — nested a!cardLayout(link: a!dynamicLink, showShadow) inside a
     padding:"NONE" container card; no "View" buttons, no bordered rows [cookbook 4.1; recipe move 1].
  5. Hand-built stamp+connector placement timeline — done/current/future encoded on multiple
     channels (chip fill, glyph color, name weight, accessibilityText) [cookbook 5.3].
- Deliberately omitted: a KPI/stat masthead. A placement is a care relationship, not a metrics
  object — Ops Control prohibits display numerals, and the coordinator's #1 question ("what state,
  what needs doing?") is answered by the status chips, timeline, and task rail instead.
```

Persona's ranked tasks: 1) see state + what needs doing now → masthead chips, progress rail,
task rail above the fold; 2) talk with the foster family → composer-first thread, the page's one
SOLID button; 3) verify facts / audit history → facts card + activity feed.

```
   │     relative time SMALL SECONDARY / body], whitespace-separated marginBelow=MORE)
   └─ [non-stacked widths] SECTION "Open Tasks (4)" → CARD(padding=NONE,
   │     4× linked row cards [TINY type stamp | title STRONG | tag?] + [meta | due MINIMIZE],
   │     row 1 carries the page's ONLY NEGATIVE tag: OVERDUE
   │     + footer linked row "View completed (9) ›" ACCENT STRONG centered)
      SECTION "Recent Activity" → CARD(padding=NONE, 5× event rows [TINY actor stamp |
         actor STRONG + action / timestamp SMALL SECONDARY] + footer "View full history (23) ›")
```

**Phone behavior (stated per core/mobile.md):** main columns `stackWhen: {"PHONE","TABLET_PORTRAIT",
"TABLET_LANDSCAPE"}` (record-view corpus default) → stack order: progress rail → **Open Tasks
(phone copy)** → animal facts → family → thread → history. The task rail swaps location via
complementary `a!isPageWidth` forks (cookbook 2.3/2.4) so tasks sit directly under the status rail
on phone instead of below the thread. Header action buttons flip `align` END→START when stacked
(cookbook 2.1); timeline node labels center on PHONE as their icon column stacks (ins-claim
recipe); billboard stays EXTRA_SHORT at all widths; header is not fixed; no grids anywhere, so
nothing needs column re-tuning. Fact-card nested 3-col rows stack to a single column on PHONE.
