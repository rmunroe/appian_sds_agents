# T1 — Metro Dispatch Board (Rose City Courier)

## 1. Design Brief

```
DESIGN BRIEF
- Use case: Dispatch supervisor triages delivery exceptions and monitors ~200 live metro deliveries, driver status, and today's throughput — desktop, all day, every day.
- Pattern + variant: dashboards / operational   [Stage 1: S1 — monitor & triage all day; many live records + statuses; she FIXES from this page]
- Recipe: Ops Control  ·  Density: 4            [Stage 2: daily-operator × clinical-technical; primary taken, no override]
  (evidence: 5 KPI cells + 12-row working list + 5-card exception queue + 6-driver rail + gauge + sparkline in one viewport; container padding "NONE" on list cards; metadata at SMALL)
- Palette (5+ hexes): page #f4f2f1 warm greige · cards #ffffff shadow-not-border · brand/accent ACCENT token (links, the sole SOLID button; renders ≈#316598 est.) + driver identity pastels #9db6d0/#d19fcb/#79b096/#9dd0aa/#eccd5f + throughput hue #45818e · semantic: NEGATIVE only on the FAILED tag + the exceptions caret, POSITIVE on good carets, LATE duotone #f8edd0/#8a6d1a, REROUTED neutral #d9d9d9 · text #54514e headings / #666666 metadata
- Header treatment: flush masthead — EXTRA_SHORT fleet-photo billboard welded to a white KPI band (double marginBelow "NONE"); no page title — the KPI numbers are the biggest text on screen
- Signature moves (Ops Control + anti-corporate menu):
  1. Flush billboard→KPI masthead: brand + fleet health read as one band — a!billboardLayout + a!cardLayout both marginBelow "NONE"; hand-built KPI cells (caps SMALL SECONDARY label, SECONDARY icon, MEDIUM_PLUS STRONG value, caret-only delta color) in a!columnsLayout(spacing:"SPARSE", showDividers) — never a!kpiField.
  2. Whole-card a!dynamicLink rows for the exception queue, driver roster, and every delivery row — shadow-not-border click targets stacked flush inside padding:"NONE" container cards (a!cardLayout(link:)).
  3. Red rationed to the truly broken state: exactly one NEGATIVE tag (FAILED) and one NEGATIVE caret (exceptions rising) per viewport; LATE demoted to pale amber duotone, REROUTED to neutral gray — triage priority is instant and the status column keeps ≤2 non-neutral hues (a!tagItem backgroundColor/textColor).
  4. Pastel identity stamps as the driver vocabulary: stable TINY a!stampField chips per driver (glyph in STANDARD ink for contrast) — color as vocabulary, not decoration.
  5. Designed empty state for the Unassigned zone: fixed-height card, char(10) centering, EXTRA_LARGE #d9d9d9 inbox icon — a healthy zone holds its footprint instead of vanishing.
- Deliberately omitted: a live map view. No verified map construct exists in the corpus, and a hero map would push the exception queue below the fold — geography rides instead on zone words in every address line, driver row, and the Zone filter. (Also omitted: analytical charts — operational variant carries status via tags, carets, and one MICRO sparkline.)
```

## 2. Layout skeleton (guidance notation)

```
HEADER-CONTENT bg=#f4f2f1 contentsPadding=STANDARD
├─ BILLBOARD h=EXTRA_SHORT (fleet photo, no overlay) marginBelow=NONE
├─ CARD(KPI-ROW ×5 dividers+SPARSE: ACTIVE NOW 203 · EXCEPTIONS 12 ▲3(neg) · ON-TIME 94.2% ▲(pos)
│       · DELIVERED TODAY 486 ▲(pos) · DRIVERS 26/31  |  ghost spacer  |  "NEW DISPATCH" SOLID LARGE)
│       ← flush to billboard (marginBelow NONE on both)
└─ COLUMNS [MEDIUM:AUTO:MEDIUM] stackWhen ≤DESKTOP_NARROW  (queue column leftmost → stacks first)
   ├─ SECTION "Exception Queue" → CARD(pad NONE:
   │     5× CARD(link: title STRONG + right-pinned tag / reason·driver + right-pinned time)
   │     └ CARD(link: "See All 12 Exceptions ›" centered ACCENT STRONG))
   │  SECTION "Unassigned" → CARD(empty state, fixed h=MEDIUM_PLUS: pale inbox icon + sentence)
   ├─ SECTION "Active Deliveries" → CARD(pad NONE:
   │     filter band [Zone dd | Status dd | right note "203 active · sorted by risk · updated 2:47 PM"]
   │     → pseudo-table header row (caps eyebrows, phone-swapped out)
   │     → 12× CARD(link: row COLUMNS [AUTO:NARROW_PLUS:NARROW_PLUS:NARROW], hairline rules,
   │                  consolidated ID+customer / address·zone · driver · status tag · ETA STRONG+promised)
   │     └ CARD(link: "See All 203 Active Deliveries ›"))     ← widest zone, ≥40% of viewport
   └─ SECTION "Driver Status" → CARD(pad NONE: 6× CARD(link: pastel stamp | name STRONG + status·zone | stops left)
      │                              └ CARD(link: "See All 26 Drivers ›"))
      SECTION "Today's Throughput" → CARD(pad MORE: gauge 68% of 715 target (#45818e)
      │                              → "DELIVERIES BY HOUR" MICRO sparkline (#45818e, axes NONE)
      │                              → 3 label/value rows: Delivered 486 · Out for delivery 203 · Awaiting pickup 26)
      SECTION "Actions" → CARD(3× OUTLINE SECONDARY FILL: Message All Drivers · Print Run Sheets · Exception Report)
```

**Phone/tablet behavior (stated per README):** body triptych stacks at `{"PHONE","TABLET_PORTRAIT","TABLET_LANDSCAPE","DESKTOP_NARROW"}` in task order — exception queue first, deliveries second, driver/throughput rail last (leftmost column = first). Masthead KPI row stacks at phone/tablet widths and drops its dividers on phone (`showDividers: if(a!isPageWidth({"PHONE"}), false, true)`); the ghost spacer column exists only at full desktop; the SOLID button flips END→START as the masthead stacks. The pseudo-table header row is swapped out on phone (`if(a!isPageWidth({"PHONE"}), {}, …)`) and each delivery row's columnsLayout stacks by default into a per-delivery card. Header is not fixed. Site page title: "Dispatch" + truck icon.
